grix in the browser

These are real grix runs. The grix kernel boots in QEMU compiled to WebAssembly, and grix's host side (the boot image, the console protocol, stdin flow control) is grix's own Rust compiled to wasm. Every run boots a fresh machine whose kernel runs exactly one Linux binary. The program sees only the files listed for it, and anything it tries without the matching capability is denied and reported. Edit the command, tick a capability, and run it again.

Hello

A static C program gets its arguments and environment, writes to stdout and stderr, and exits with status 7.

Least privilege

This program only opens a socket. Without net the kernel refuses and tells the host which capability would have allowed it. Tick net and run it again. (No traffic can leave a page. Here net only lets the socket exist.)

Only what you import

The filesystem holds exactly the imports plus a few synthetic files. Try cat /etc/shadow, or ls /.

Processes

A shell pipeline forks. Without process the shell can't fork, and the denial says why.

A shell

bash, with busybox for the rest, in TTY mode: the program's stdio is a pseudo-terminal inside the sandbox, with line editing, job control and Ctrl-C. Try ls -l / | head, sleep 100 then Ctrl-C, or echo hi > /tmp/x (it needs fs_write: stop, tick it and start again). Without process, nothing outside bash runs.

A Python REPL

Python's own interactive prompt, in the same kind of terminal. Try import os; os.listdir('/'), or open('/tmp/x', 'w') without fs_write.

Threads and Go

Unmodified Go: its runtime starts threads, and os/exec forks, pipes and kills children.

Python

Alpine's Python 3.12, unmodified, with its standard library imported as a root filesystem. Try opening a socket or writing a file without the capability.
